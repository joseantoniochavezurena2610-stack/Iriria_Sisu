# Architecture — a 100 % web app

## In one sentence
A static page (HTML + CSS + JavaScript, no server) that loads pre-processed NASA data as JSON and runs the rotation engine **in the farmer's browser**. GitHub Actions downloads and refreshes the data automatically.

```
              ┌──────────────── GitHub Actions (every Monday / when scripts change) ─────────────┐
NASA POWER ──▶│ scripts/fetch_data.py        → web/data/guanacaste/climate_<canton>.json          │
NOAA CPC   ──▶│                              → web/data/enso.json  (El Niño / La Niña per month)  │
SoilGrids  ──▶│ scripts/fetch_soilgrids.py   → soil_reference.json   (optional)                   │
IMERG      ──▶│ scripts/fetch_imerg.py       → imerg_monthly.json    (optional, Earthdata)        │
Team CSV   ──▶│ scripts/catalog_to_json.py   → web/data/crops.json                                │
              └──────────────────────────────────┬──────────────────────────────────────────────┘
                                                 │ automatic commit
                                                 ▼
                    Static hosting (GitHub Pages + custom domain)  ──▶  farmer's browser
                                                                         web/js/app.js     (interface)
                                                                         web/js/climate.js (scenarios)
                                                                         web/js/engine.js  (engine)
```

## Why this design
| Need | Solution |
|---|---|
| 100 % web, opens on a phone | Responsive static page |
| Running cost ≈ $0 | No server or database; free hosting |
| The demo must not fail | Data precomputed in the repo; if a canton is missing, the app tries a live POWER download |
| The farmer must not depend on sensors | Everything comes from a form |
| Always-fresh data (ongoing El Niño) | Weekly `data` workflow |
| Defensible in front of judges | Transparent rule-based engine with automated tests |
| Privacy | Nothing is stored or sent: the calculation happens in the browser. The phone's location only picks the nearest canton |


## Running locally
```bash
python3 -m http.server 8000 --directory web   # open http://localhost:8000
npm test                                       # engine tests (Node 20+)
python3 scripts/catalog_to_json.py             # after editing the CSV
python3 scripts/fetch_data.py                  # download NASA data (needs internet)
```
> Opening `index.html` with a double click does not work (the browser blocks reading the JSON files). Always use a local server.

## Publishing
`publish.yml` workflow (off by default):
1. Settings → Pages → *Source*: **GitHub Actions**.
2. Settings → Secrets and variables → Actions → *Variables* tab → `PUBLISH_PAGES` = `true`.
3. Every push to `main` and every data update republishes the site.

Equivalent alternatives (all free for static sites): Cloudflare Pages, Netlify, Vercel. Point them at the `web/` folder with no build step.

## Domain (owner: José Pablo)
### Requirements
- Short, easy to say on a farm and to type on a phone. Ideas: `iririasisu.app`, `iririasisu.com`, `iririasisu.cr`, `sisu.cr`. Avoid accents in the domain.
- **HTTPS required** (the phone's location only works over HTTPS). GitHub Pages provides it for free.
- Yearly payment: record who the holder is and the expiry date, and turn on auto-renewal so the site does not go down after the contest.
- Confirm the registrar lets you edit DNS records (A, AAAA, CNAME).

### Steps with GitHub Pages
1. Buy the domain (NIC Costa Rica for `.cr`; any registrar for `.com`/`.app`).
2. At the registrar, create the DNS records:
   - Root domain: **A** records to `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` (and AAAA for IPv6 if wanted).
   - `www`: **CNAME** record to `joseantoniochavezurena2610-stack.github.io`.
   - Check these IPs against GitHub Pages' official documentation on the day you set it up.
3. Create the file `web/CNAME` containing a single line: the domain (e.g. `iririasisu.app`).
4. Settings → Pages → *Custom domain* → enter the domain → *Enforce HTTPS*.
5. Recommended: *verify the domain* in the GitHub account/organisation settings so nobody else can claim it.
6. Test on a phone using mobile data (not only wifi).
